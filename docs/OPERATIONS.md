# Configuration and operations

## Environment reference

All values use the `ADBOT_` prefix and are read from environment variables first,
then `../.env` relative to the backend working directory. Do not commit `.env`.

| Variable | Default / behavior |
| --- | --- |
| API_KEYS | Required; comma-separated secrets, each at least 32 characters |
| ENVIRONMENT | `development`; production enforces PostgreSQL, Redis, operator domains and fixture disabled |
| DATABASE_URL | `sqlite:///./adbot.db`; production `postgresql+psycopg://…` |
| REDIS_URL | Empty locally; production `redis://redis:6379/0` |
| POSTGRES_PASSWORD | Compose database password, generated by init script |
| AUTHORIZED_DOMAINS | Operator host allowlist; required in production |
| CORS_ORIGINS | `http://localhost:5173,http://127.0.0.1:5173` |
| FIXTURE_MODE | `false`; development-only exemption for exact fixture endpoint |
| FIXTURE_PORT | `8765` |
| MAX_CONCURRENCY | `2`, maximum `8`, globally enforced by SQL slot leases |
| LEASE_SECONDS | `90`, minimum `30` |
| ARTIFACT_DIR | `./data/screenshots` |
| RETENTION_DAYS | `30`; terminal results and captures expire |
| RATE_PER_MINUTE | `120` API requests per workspace key |

Keys act as isolated workspace identities, derived by hashing each key. Sharing
a key shares a workspace. Separate keys cannot inspect each other's targets,
jobs, results, or artifacts. This release does not offer user accounts, team
roles, invitation flows, encrypted site credentials, or authenticated-site login.
Changing a key changes its workspace identity; plan a data migration before
rotation if ownership must persist. Never place a backend key in a Vite build
environment variable. The dashboard uses sessionStorage, clears it on disconnect,
and sends it only in authorization headers.

## Production deployment

1. Generate secrets with `python scripts/init_env.py`. Protect the resulting file.
2. Set environment to production and explicit operator domains. Use a dedicated
   host/container service account. Each API key holder must be a trusted operator.
3. Run `docker compose up -d --build --wait`. The migration container must exit
   successfully before workers/API start. Inspect `docker compose ps -a`.
4. Place a TLS reverse proxy in front of loopback port 8080 and configure the
   public origin. Keep PostgreSQL, Redis and API ports private.
5. Enforce network-level browser egress: deny metadata, private/link-local,
   loopback except the per-job proxy, and non-proxied browser traffic. The in-job
   proxy must reach only approved public services. Validate browser-engine-specific
   channels. Do not treat application request routing as a replacement for a
   network namespace/firewall. A compromised browser is outside that boundary.
6. Apply host hardening and browser sandbox settings appropriate to your platform.
   Playwright's Chromium launch uses its default sandbox configuration; deploy
   only trusted, approved targets until OS sandbox/egress tests are complete.
7. Observe real memory use. The Compose worker limit is 2 GiB with two browser
   jobs and 1 GiB shared memory. The API and scheduler have separate limits.
   Reduce concurrency if browsers are killed or memory is tight. Visible browser
   mode requires a graphical display; production containers should use headless.
8. Test crashes, network loss, redis recovery, and restore backups on the actual
   deployment. Verify all browser engines you enable. Keep browser/runtime and
   package dependencies patched together and rerun the tests after upgrades.

Production startup checks configuration, not deployment certification. The
readiness endpoint checks schema accessibility and Redis; it does not prove
workers are running. Running jobs expose lease-backed heartbeats internally.
Monitor worker process/container health and queue age externally as well.

## Persistence, backups and retention

Compose uses named `postgres`, `redis`, and `artifacts` volumes. The SQL queue,
frontier and results are authoritative; Redis wakeups may be lost without losing
jobs. Do not delete volumes during routine restarts.

Back up PostgreSQL regularly, for example:

```sh
docker compose exec -T postgres pg_dump -U adbot -d adbot -Fc > adbot-backup.dump
```

Restore into an isolated database first:

```sh
docker compose exec -T postgres pg_restore -U adbot -d adbot_restore --no-owner < adbot-backup.dump
```

Create `adbot_restore` beforehand. Back up the artifact volume separately using
your host's volume backup tool, with filesystem ownership preserved. Encrypt
backup storage. Verify a restored job's page results and screenshot links. For
SQLite, stop all writers and copy the database or use SQLite's backup API; do not
copy only the live main file while WAL writers are active.

The scheduler deletes old terminal jobs and expired PNGs hourly based on
`RETENTION_DAYS`. Paused/running/queued jobs are retained. Website deletion removes
its database history immediately; orphaned captures expire through retention.
Do not set retention beyond your actual authorization to store target content.

## Logs and failures

The API emits JSON method/path/status/duration records without bearer headers.
Workers emit job ID/status/error category; scheduler failures emit categories.
Uvicorn/httpx may emit separate access logs. Page URLs and workflow extraction
results are private persisted data, but can contain query parameters or page
content. Do not crawl secret-bearing URLs or store sensitive captures unless
approved. No login credentials are accepted or stored.

HTTP response codes, page error categories and navigation timings persist.
A completed crawl means traversal finished; individual 404/403/500 pages remain
visible as results. A navigation timeout is recorded as a page error. Rate-limit
exhaustion, browser/session failure, and workflow assertion errors fail the job.
Cancellation may leave the currently visited frontier URL in `visiting`; manual
retry creates a fresh job. Expired-lease recovery resets unfinished URLs.

## Troubleshooting

| Symptom | Action |
| --- | --- |
| API refuses to start | Generate `.env`; verify each API key has 32+ characters; run from `backend/` |
| Readiness 503 / missing tables | Run `python -m alembic upgrade head`; check database/Redis connectivity |
| Jobs remain queued | Start `python -m app.worker`; inspect process logs and expired leases |
| No scheduled jobs | Start `python -m app.scheduler`; verify enabled flag, cron and timezone |
| Browser executable missing | Run `python -m playwright install chromium firefox webkit` in the same virtual environment |
| Browser shared-library error on Linux | Run `python -m playwright install --with-deps chromium firefox webkit` with OS package permissions |
| Browser exits under load | Inspect container OOM events; reduce concurrency and page complexity |
| Page styles/scripts absent | Add explicitly authorized resource/CDN domains; all unlisted subresources are blocked |
| robots policy blocks page | Verify robots response and rules; 5xx/auth failures fail closed |
| External/internal redirect blocked | Correct target/operator allowlists; internal destinations remain forbidden |
| 401 after key change | Workspace identity follows key; use original key or migrate ownership explicitly |
| API returns 429 | Wait for the next minute or raise the per-key rate limit appropriately |
| Pause appears delayed | Pausing occurs between page visits/actions; cancellation is the prompt stop control |
| Captures unavailable | Check artifact volume/permissions, owning key, and retention expiration |
| End-to-end test fails to bind | Stop local development processes on 8000, 5173, 8765 before testing |

HTTP/HTTPS public access and permission to automate are prerequisites for normal
targets. CAPTCHA, stealth, proxy rotation, credential automation, purchases,
form submissions, ad clicks and artificial engagement are not supported.
