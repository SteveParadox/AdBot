# Execution audit

Task creation in `agent/api.py` validates ownership, permissions and budgets and snapshots the website. `jobs.py` claims an execution lease. `worker.py` starts the isolated runner, watches cancellation and heartbeat, and publishes a verified result under the lease. `browser.py` and `agent/controller.py` enforce navigation and interaction policies. `agent/semantic_observer.py` supplements accessible snapshots with bounded DOM metadata and binds controls to their live document. `agent/runner.py` observes, plans, selects, reviews and executes each step and checkpoints in `AgentTask.memory`. `agent/model.py` compacts, reserves, calls and settles provider requests. `agent/planning.py` handles completion dependencies, while `extraction/` handles explicitly configured schemas, records and exports. `AgentPanel.tsx` presents job, plan, activity and verification state.

| --- | --- | --- | --- |
| Every collection step required inference | `runner.py` delegates action choice even for repeated cards and Next | Select a bounded directory strategy when both intent and visible structure support it | Strict eligibility, dynamic fixture and source coverage tests |
| Early token rejection | `model.py` estimates one token per prompt character, then reserves output. `runner.py` also holds primary fallback tokens. Displayed remaining tokens is the overall balance | Estimate request admission separately from actual usage, preserve output reservation, expose rejection details | Audit budget tests, keep byte upper bound for unknown models |
| Large observations and repeated capture | Observer binds up to 80 controls twice per step. The provider sees a separate compacted prompt | Smaller semantic capture for directory steps, keep full diagnostics on general path | Verify forward controls survive the bound and stale controls resolve safely |
| Visual state mistaken for progress | Scroll and focus alter raw fingerprints; retries key off volatile element IDs | Scope traversal to new record IDs. Track equivalent action identity independently of geometry | Duplicate page and unrelated UI change regressions |
| Evidence and completion conflated | Collection plan is satisfied by any evidence and model verification trusts its scope | Require stable visible directory total, exact unique coverage, classified rows and terminal pager | Incorrect totals, unknown categories and interrupted coverage yield partial results |
| Provider failures | Shared SQL admission and cooldown, ordered failover and pause-aware waits already exist | Keep the route and budget checks; avoid model calls for supported traversal | Provider-offline browser fixture and existing provider regression suite |
| Useful partial evidence hidden | Worker only publishes a completed result and dashboard only renders complete claims | Publish source-backed directory progress and partial results on failure | Check lease, abort, failure and UI representation |
