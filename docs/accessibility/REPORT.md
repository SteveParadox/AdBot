# Accessibility-aware interaction upgrade

## Scope and initial audit

This extends the existing Adbot runner, planner, native Playwright interactions, SQL steps/checkpoints, egress policy and dashboard. Earlier local changes were preserved. Groq remains the configured primary model and Qwen the configured fallback. No production service was restarted, deployed, or given new credentials.

| Capability before this change | Classification | Finding |
|---|---|---|
| Accessibility inspection | Partial | Bounded body ARIA snapshot existed, separate from the small DOM registry. |
| Semantic roles | Defective | Radios/numeric inputs could be classified as textboxes; most custom roles and native dialogs/tables were omitted. |
| Accessible names | Defective | Handwritten naming gave aria-label priority over aria-labelledby; browser-computed semantics were not authoritative. |
| ARIA state/relationships | Partial | Expanded/disabled/form metadata existed; checked, selected, descriptions, active descendant, live feedback and readonly handling were incomplete. |
| Keyboard navigation | Partial | Tab/arrows/Escape existed; Enter/Space activation and control-aware permission checks were absent. |
| Focus management | Partial | FOCUS and focus change detection existed; modal containment/restoration diagnostics were missing. |
| Visibility/actionability | Implemented, requires improvement | Native click trials and enabled checks existed; semantic eligibility and modal boundaries needed integration. |
| Form association | Partial | Closest form was used; external native form ownership, selection controls and validation needed work. |
| Dynamic widgets | Partial | Hover, fill, wait and scrolling existed; native select/check and custom ARIA outcomes were missing. |
| Element identity | Defective | Semantic fingerprint IDs existed, but identical replacement nodes could inherit a locator's meaning. |
| Modal interaction | Missing | No active-modal scope or focus containment diagnostics. |
| Result verification | Implemented, requires improvement | Exact input values, expected text, observed UI changes and separate goal verification existed; boolean/select/disclosure/tab states needed stronger checks. |
| Screen-reader semantics | Partial | ARIA text was available; no browser-computed role/name registry or manual assistive-technology certification. |
| Accessibility-aware replanning | Partial | Durable bounded recovery existed; rich control eligibility/context was not supplied to planning. |

## Architecture and changed components

`agent/observe.py` remains the compatibility entry point. `agent/semantic_observer.py` owns observation assembly, context-aware locator resolution, sensitive-value scrubbing and physical-node identity. `agent/semantics.py` contains bounded DOM metadata. Accessible role/name computation comes from public Playwright `Locator.aria_snapshot()`, with a disclosed DOM fallback when a native semantic header is unavailable; this does not invent another accessible-name standard or use private Playwright internals.

Each observation reads up to 2,000 candidate DOM nodes and inspects at most 80 candidates with eight concurrent read-only inspection operations. Active dialog context, focus, interactive eligibility, task terms and viewport position determine priority. Relevant native HTML elements, explicit roles, tabindex and live regions are covered. Hidden/disabled controls can be described but cannot receive an authorized action. Native dialogs, tables and output elements are included alongside custom widgets. The model receives a smaller bounded representation rather than the raw diagnostic structure.

Elements include native role/name, DOM descriptions/labels, public current value, form owner/purpose/destination, validation feedback, focusability, focus, expanded/checked/selected state, readonly/required/invalid state, controls/label/description references, active descendant, live/busy feedback, nearby heading/landmark, bounds, visibility and locator strategy. Candidate eligibility is **not** a guarantee of pointer hit testing or successful operation: native Playwright action-specific checks still run immediately before input. Static role containers are not treated as interactive merely because they exist.

Resolution tries exact role/name in an identified region/dialog or heading context, global exact semantics, associated labels, placeholders, test IDs and unique DOM IDs/destinations. A bounded DOM-derived fallback remains for imperfect markup. Unresolved duplicate semantic controls fail explicitly; the resolver never silently takes the first matching Delete button. Unknown roles fall back to generic DOM context rather than crashing role selectors. No model-generated CSS, XPath, JavaScript or coordinates are accepted as new action arguments.

A WeakMap held inside a JSHandle assigns physical node identities without changing DOM attributes, ARIA, browser globals/prototypes or navigator properties. Bound node handles are released on a new observation. Discovery and context resolution use native locators; final targeted input uses the one observed node so Playwright cannot silently retarget an identical replacement. This is a deliberate limited use of ElementHandle for identity-sensitive dispatch, rather than using stale handles as a general browsing strategy. Navigation/document changes invalidate the registry; an observation interrupted by navigation is retried once, then refused if it cannot be coherent. Old document text cannot be attributed to a new URL.

`agent/controller.py` rechecks identity, current semantics, form ownership, state and modal boundaries. `agent/interaction.py` performs real native input and bounded outcome checks. `contracts.py` adds SET_CHECKED, SELECT_OPTION, Enter and Space; `planning.py`, `memory.py`, `runner.py`, `jobs.py` and `worker.py` integrate permissions, meaningful action keys, durable traces and conservative crash/no-replay handling. `model.py` supplies semantic context and compacts state/history while preserving evidence and the original task contract. The fixture model remains explicitly a test double, never a production task router.

`SemanticTrace.tsx`, its tests and `AgentPanel.tsx` expose selected role/name, locator strategy, eligibility, failed resolution, native keys, before/after focus, restoration/recovery, recognized controls, observation size/truncation and real outcomes. React escapes hostile labels as text. Existing task plans, evidence, reviews and execution controls remain available.

Other changed/added artifacts: local `/agent/accessibility` fixture endpoint; `backend/testsupport/accessibility.html`; accessibility, safety and agent integration tests; dashboard E2E coverage; `scripts/benchmark_semantics.py`; `scripts/audit_accessibility.py`; this report and raw measurements. The existing `.env`, provider preferences, unrelated local files and prior reports were not replaced. No additional application or package dependency was required.

## Keyboard, forms and dynamic controls

- Native Tab/Shift+Tab, arrows, Escape, Home/End and page navigation keys remain available. Enter/Space activation requires an observed focused target and receives the same one-operation authorization path as a click. Form edits, checkbox/radio/switch/select changes and editing keys require the existing form-input permission. Secret/payment/file fields and readonly edits remain unavailable. A new action does not grant arbitrary POST access.
- Native select options are selected by an exact observed label/value and checked afterward. Checkboxes/radios use native checked setters; custom switches/checkboxes use an actual click plus observed ARIA checked-state verification. Radios cannot be blindly unchecked. Already-satisfied selections/focus are verified without unnecessary input/waits.
- Text, email, numeric and supported date/time inputs use native fill/type, then exact actual-value verification. Unknown values are not supplied by the engine: the action must provide the intended text. The model should ask for missing values. No secret autofill, file upload or payment capability was added.
- Submission checks the current form's required/native validation feedback and destination. Existing click authorization/review behavior remains in force; accessibility is not a new submission permission. A successful native method call does not establish backend completion.
- Custom comboboxes, menus, tabs, trees and grids can be focused and operated with actual supported keys or observed options. The engine does not assume that adding an ARIA role gives a widget working keyboard behavior. Arrow keys must produce observed state/focus changes; exact requested outcomes still require appropriate evidence.
- Clicking a boolean control, tab or disclosure checks its expected state; controlled content visibility is checked where applicable. Generic clicks with no confirmed change remain explicitly unverified. Separate task completion verification remains authoritative.
- Modal background controls are excluded from interaction. Focus containment and restoration are recorded. When native Tab traversal leaves the active modal, one bounded real-focus recovery attempt selects the appropriate first/last eligible control in that modal; no website focus handler or ARIA attribute is rewritten. Unknown opener identity produces an unknown restoration result, not an invented success. Nonmodal dialogs do not block the rest of the page.
- A maximum of 32 consecutive traversal keys prevents endless Tab loops; semantic FOCUS offers a direct route. Existing task step/token/deadline/cancellation and retry limits still apply. An input exception after possible dispatch is never automatically replayed. The new selection actions are included in worker crash/expired-lease ambiguity protection.

## Privacy, efficiency and planning

Sensitive field values are withheld from semantic observations, native snapshots exposed to the model are reduced to sanitized semantic headers, and known protected values are scrubbed from outcomes/errors. Editable fields are masked in screenshots. Diagnostics avoid recording raw input values in focus/locator traces. This is conservative field/known-value protection, not a universal data-loss-prevention guarantee for arbitrary sensitive prose elsewhere on a website.

Working context includes the active subtask, relevant control availability, dialog context, recent semantic changes and live feedback. Per-step diagnostic observations remain durable. Prompt compaction drops redundant/default metadata, bounds option lists, favors goal-relevant choices and records model truncation. Recent actions are summarized without large traces. Crucially, evidence is retained rather than discarding all session memory when a large semantic observation must shrink. Original constraints are never dropped to fit a request. Oversized immutable requests fail safely.

## Measured behavior and audit findings

[BASELINE.json](BASELINE.json) records the initial observer: 28 controls, seven reported roles, 10,731 serialized observation characters, and 263.293/119.284/124.376ms across three Chromium reads. [POST.json](POST.json) records the upgraded observer: 48 included nodes, 25 roles, 893.762/727.030/823.655ms reads, and roughly 55–57K raw diagnostic characters. The benchmark's actual bounded model requests were 13,514/12,863/12,863 characters with 20 retained controls under an 18,000-character cap. These are local browser measurements, not live LLM tokens or task-accuracy scores. Richer native semantics cost additional protocol calls and raw diagnostic bytes; no general latency reduction is claimed. A malformed nested HTML quote in the new virtual-list fixture was corrected during testing, so the initial and final fixture observations are not a strict performance A/B experiment.

Reproduce with `.venv\Scripts\python.exe scripts/benchmark_semantics.py --output docs/accessibility/POST.json`. It uses a local static fixture, isolated in-memory configuration and a real Chromium browser, never the production database or a model provider. The bounded request measurement uses an 18,000-character limit and the actual Decision schema, not a token estimate represented as provider usage.

The complete dashboard semantic workflow finished in five browser steps with seven model calls and 5,600 fixture-reported tokens. Those usage counts come from the deterministic test model; they are not live Groq/Qwen usage, billing measurements or interpretation-accuracy scores.

[AXE_RESULTS.json](AXE_RESULTS.json) records axe-core 4.10.3, its bundle SHA-256, rule findings and incomplete checks. The accessible reference had no WCAG-tagged violations. The intentionally imperfect semantic laboratory had `aria-required-children`; the known bad reference produced `label` and `aria-required-attr`. These were reported rather than fixing destination attributes to make an audit green. Automated axe results do not certify keyboard behavior, screen-reader usability or every WCAG requirement.

Run `scripts/audit_accessibility.py --axe <trusted axe.min.js> --output docs/accessibility/AXE_RESULTS.json` with the workspace Python. The audit accepts a separately obtained trusted bundle and only injects it into controlled local test pages. The actual 4.10.3 bundle came from the versioned cdnjs distribution using normal TLS verification; npm registry requests failed with ECONNRESET and Windows curl reported an offline certificate-revocation service. No certificate verification or application network policy was disabled. The bundle is not an application runtime dependency or injected into user destinations.

Primary references: [Playwright semantic locators](https://playwright.dev/python/docs/locators), [ARIA snapshots](https://playwright.dev/python/docs/aria-snapshots), [locator APIs](https://playwright.dev/python/docs/api/class-locator), [handle guidance](https://playwright.dev/python/docs/handles), [WAI-ARIA keyboard practices](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/), and [combobox patterns](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/). The local runtime predates the newer Playwright AI snapshot/ref APIs; none of those newer APIs was assumed available.

## Post-implementation audit and limits

Confirmed defects corrected include accessible-name precedence, missing native dialog/table candidates, generic radio/numeric classification, lack of selection setters, duplicate-name fallback ambiguity, identical-node replacement retargeting, readonly/input authorization gaps, unverified disclosure/tab states, modal focus leaving document scope, live feedback omitted from compact reasoning, excessive trace history displacing evidence, transient inspection failure handling, and mixed-document observation provenance. Integration testing also corrected ElementHandle.focus argument incompatibility, a conflicting diagnostics field name, a malformed local fixture control, and local test-port invocation collisions. Screenshot review caught a premature result panel while the worker was still finishing; verified results now appear only after verified completion and completed task status. These failures were fixed and rerun, not hidden by disabling tests.

Supported coverage is top-document candidate discovery with bounded native semantic reads. Closed shadow roots, arbitrary cross-origin frames, image-only/coordinate workflows, inaccessible widgets without working native event behavior and unsupported control patterns require another supported route or user intervention. Native JavaScript alert/confirm/prompt dismissal retains the existing policy; DOM dialog/alertdialog support does not add permission to accept those prompts. There is no universal keyboard script, CAPTCHA/access-control bypass, stealth plugin or fingerprint override. Native browser configuration, UA/locale/viewport/timezone and pinned session identity remain unchanged.

Static DOM descriptions are supplemental metadata, not full platform accessibility-tree or assistive-technology certification. Physical-node anchoring prevents replacement retargeting; it cannot freeze a hostile site's event handlers or semantic changes at the instant of a real input. Network/method/domain policies continue to enforce the external boundary. Full script provenance and malicious-site behavioral isolation are not claimed.

Local tests use Windows/Python 3.11 and the existing Playwright installation. Reinstall pinned dependencies and run deployment/CI checks before a release; local test-double model behavior is not evidence of live Groq/Qwen reasoning quality. Manual screen-reader testing, international widget behavior beyond the tested locale, broader real-site coverage and high-load browser performance remain release evaluation work. See [VERIFICATION.md](VERIFICATION.md) for exact executed results and the final acceptance matrix.

## Using and extending the implementation

Enable form input for authorized form/selection work. Inspect the semantic control diagnostics when a target is ambiguous, unavailable or readonly; use explicit context or clarification rather than guessing. Prefer a semantic FOCUS followed by a supported key for a custom widget. Use SET_CHECKED for an intended boolean state and SELECT_OPTION only for an observed native option. Inspect real confirmation and cited evidence before treating a submission as complete. An uncertain write requires external inspection before starting another task.

Developers should add a controlled component fixture and actual native keyboard/state assertions before declaring a new widget pattern supported. Keep selector resolution, authorization, physical identity and outcome verification separate. Preserve observation caps, request budgets, disclosure of DOM fallbacks and complete evidence checks. Run fixtures on each supported engine and keep intentional accessibility violations visible in audit reports.
